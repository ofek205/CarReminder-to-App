# UX: דמו אינטראקטיבי בקטע "המסכים שתשתמשו בהם"

> שלב `ux` בשרשרת ה-Playbook. קודמו: [spec-marketing-interactive-demo.md](spec-marketing-interactive-demo.md).
> הבא בתור: `designer`. נכתב 2026-09-10.

## 1. מטרת החוויה

לא "לשים אפליקציה במסגרת". המטרה: **שמבקר יבין תוך עשר שניות איך המוצר מרגיש ביד, בלי להירשם ובלי להרגיש שהוא נכנס למלכודת.**

מדד ההצלחה החוויתי: המבקר נוגע במסך אחד לפחות מעבר למסך הפתיחה. אם הוא רק הסתכל, הדמו נכשל והתמונה הסטטית הייתה זולה יותר.

## 2. מסע המשתמש

```
גלילה לקטע
   │
   ├── הקטע מחוץ לתצוגה ──▶ תמונה סטטית. אפס בייטים של אפליקציה
   │
   ▼ הקטע נכנס לתצוגה
תמונה סטטית + שכבת הזמנה ("התנסו במסכים")
   │
   ├── המבקר מתעלם וגולל הלאה ──▶ שום דבר לא נטען. סוף
   │
   ▼ לחיצה / Enter
   ├── מובייל ──▶ דיאלוג מסך מלא
   └── דסקטופ ──▶ המסגרת במקום
   │
   ▼
מצב טעינה בתוך המסגרת
   │
   ├── הצליח ──▶ מסך הבית עם כלי ההדגמה
   │                │
   │                ├── ניווט למסך אחר ──▶ נטען בדמו
   │                ├── נגיעה בפעולת כתיבה ──▶ פופ-אפ המרה
   │                └── יציאה: Esc / כפתור סגירה / גלילה הלאה
   │
   └── נכשל או חרג מזמן ──▶ חזרה שקטה לתמונה הסטטית
```

**הענף הקריטי הוא האחרון.** הוא חייב להיראות כמו שום דבר לא קרה, לא כמו כישלון.

## 3. מבנה המסך

### מצב א: מנוחה (ברירת מחדל)

הקטע נראה כמו היום, בתוספת שכבת הזמנה על הטלפון.

```
┌──────────────────── דסקטופ, RTL ────────────────────┐
│                                                      │
│   ┌──────────────────┐   ┌──────────────────────┐   │
│   │   [מסגרת טלפון]  │   │  המסכים שתשתמשו בהם  │   │
│   │                  │   │                      │   │
│   │  תמונה סטטית     │   │  ○ מה מתקרב          │   │
│   │                  │   │  ○ הרכבים שלי        │   │
│   │  ╔════════════╗  │   │  ○ המסמכים שלי       │   │
│   │  ║ ▶ התנסו    ║  │   │  ○ מצא מוסך          │   │
│   │  ║   במסכים   ║  │   │  ○ שאלות על הרכב     │   │
│   │  ╚════════════╝  │   │                      │   │
│   └──────────────────┘   │  ✓ יתרון  ✓ יתרון    │   │
│   בלי הרשמה · אפשר לצאת  └──────────────────────┘   │
└──────────────────────────────────────────────────────┘
```

הכפתור יושב **מעל** התמונה במרכז אופטי, לא מתחתיה. התמונה עצמה נשארת לחיצה כדי לא לשבור את ההתנהגות הקיימת של הגדלה.

מתחת למסגרת, שורה אחת שקטה: **"בלי הרשמה · אפשר לצאת בכל רגע"**. זו הסרת החרדה, וזה מה שמזיז אנשים ללחוץ.

### מצב ב: פעיל, דסקטופ

```
┌──────────────────────────────────────┐
│  ┌────────────────────────────────┐  │
│  │ תצוגת הדגמה            ✕ סגירה │  │ ← סרגל בקרה, מחוץ ל-iframe
│  ├────────────────────────────────┤  │
│  │                                │  │
│  │   [ האפליקציה החיה, 390px ]    │  │
│  │                                │  │
│  │   הניווט האמיתי של האפליקציה   │  │
│  │                                │  │
│  └────────────────────────────────┘  │
│  הנתונים להמחשה בלבד                 │
└──────────────────────────────────────┘
```

**סרגל הבקרה חייב להיות מחוץ ל-iframe.** אם כפתור הסגירה יושב בפנים, מבקר שנתקע בתוך האפליקציה לא ימצא מוצא, וזו בדיוק המלכודת שהופכת דמו לחוויה עוינת.

### מצב ג: פעיל, מובייל

לא מסגרת בתוך מסגרת. דיאלוג מסך מלא:

```
┌─────────────────────┐
│ תצוגת הדגמה    ✕   │ ← sticky, גובה 56px, אצבע מגיעה
├─────────────────────┤
│                     │
│   האפליקציה, מלא    │
│                     │
│                     │
├─────────────────────┤
│ הנתונים להמחשה      │
└─────────────────────┘
```

הכפתור ✕ בפינה שהאגודל מגיע אליה, לא בפינה הרחוקה.

### מצב ד: פופ-אפ ההמרה

נפתח **רק** בנגיעה בפעולת כתיבה אמיתית. לעולם לא מעצמו, לעולם לא בטיימר.

```
┌───────────────────────────────┐
│  זו תצוגת הדגמה               │
│                               │
│  כדי להוסיף רכב משלכם         │
│  צריך חשבון.                  │
│                               │
│  ┌─────────────────────────┐  │
│  │   הורדת האפליקציה       │  │ ← ראשי
│  └─────────────────────────┘  │
│  ┌─────────────────────────┐  │
│  │   כניסה לחשבון          │  │ ← משני
│  └─────────────────────────┘  │
│                               │
│  חזרה לדמו                    │ ← קישור טקסט, לא כפתור
└───────────────────────────────┘
```

**"חזרה לדמו" הוא לא ויתור, הוא מה שמונע נטישה.** מבקר שמרגיש לכוד סוגר את הטאב.

## 4. רכיבים

| תפקיד | רכיב |
|---|---|
| דיאלוג מובייל | `<dialog>` נייטיב, כמו ה-`cm-lightbox` הקיים בעמוד. עקבי, מקבל `Esc` בחינם |
| פופ-אפ המרה | `<dialog>` בתוך ה-iframe, כי הוא צריך לחסום את האפליקציה |
| שכבת הזמנה | `<button>` אמיתי. **לא** `div` עם `onClick` |
| סרגל בקרה | markup של האתר, מחוץ ל-iframe |
| נפילה לתמונה | ה-`MarketingPhone` הקיים, בלי שינוי |

הדמו לא משתמש ב-shadcn של האפליקציה בשכבת האתר. הוא חי בשפת ה-CSS של `Marketing.css`, שהיא עצמאית.

## 5. עקרונות אינטראקציה

- **הטעינה לא קופצת.** הקונטיינר שומר גובה זהה לפני, במהלך ואחרי. אפס CLS.
- **מעבר רך אחד** בהחלפת התמונה ב-iframe, כ-200ms. תחת `prefers-reduced-motion` נעלם.
- **בורר המסכים ממשיך לעבוד.** במצב מנוחה הוא מחליף תמונה. במצב פעיל הוא מקפיץ את הדמו למסך המבוקש. אותה קליקה, שתי משמעויות, לפי המצב.
- **גלילה בתוך הדמו לא חוטפת את גלילת העמוד.** `overscroll-behavior: contain` על המסגרת, אחרת המבקר נתקע.
- **יציאה בשלוש דרכים:** ✕, `Esc`, וגלילה אל מחוץ לקטע.

## 6. היררכיה ויזואלית

במצב מנוחה, סדר המשיכה: **כפתור ההזמנה** ← כותרת הקטע ← בורר המסכים ← השורה המרגיעה.

הכפתור מנצח את הכותרת בכוונה. הכותרת מסבירה, הכפתור משכנע.

במצב פעיל ההיררכיה מתהפכת: **האפליקציה עצמה** ← כפתור הסגירה ← הכיתוב. סרגל הבקרה חייב להיות נוכח וקריא, אבל שקט. אם הוא בולט מהאפליקציה, הוא מזכיר למבקר שהוא מסתכל על פרסומת.

## 7. מצבים לעיצוב

| מצב | מה רואים |
|---|---|
| מנוחה | תמונה סטטית + שכבת הזמנה + שורת הרגעה |
| טעינה | שלד בתוך המסגרת. **לא ספינר בלבד**, כדי לא לחזור על באג הספינר הנצחי של הפרויקט |
| פעיל | האפליקציה + סרגל בקרה + כיתוב הדגמה |
| ריק | לא קיים. הדמו תמיד מגיע עם כלי הדגמה. אם איכשהו אין, נופלים לתמונה |
| שגיאה / חריגת זמן | חזרה שקטה לתמונה הסטטית. **בלי הודעת שגיאה**, המבקר לא עשה כלום ולא צריך להתנצל בפניו |
| אופליין | תמונה סטטית. שכבת ההזמנה לא מוצגת בכלל, כדי לא להבטיח משהו שלא יעבוד |
| פעולה חסומה | פופ-אפ ההמרה |
| `reduced-motion` | בלי מעברים |

## 8. סיכוני שימושיות, וההמלצות

### 1. הקטנה שוברת את הנגישות. זה חוסם.

המסגרת היום `245px` ([Marketing.css](../src/pages/Marketing.css), `.cm-phone`), והאפליקציה צריכה `390px`. הקטנה ל-0.63 הופכת אזור מגע של 44px ל-**28px**, מתחת לכל רף סביר.

**המלצה: אסור להקטין דמו אינטראקטיבי.** מסגרת הדמו חייבת להכיל 390px ביחס 1:1. בדסקטופ יש מקום, עמודת הגריד רחבה מספיק. במובייל זה ממילא מסך מלא.

**זו החלטה שעוברת ל-`designer`:** מסגרת הטלפון בקטע הזה גדלה, או שהגריד משתנה. התמונה הסטטית יכולה להישאר 245px, אבל אז המעבר בין המצבים קופץ, וזה מחזיר את בעיית ה-CLS. הפתרון הנקי הוא שהקטע הזה יעבוד ב-390 משני צדי המעבר.

### 2. הפופ-אפ יהפוך למעצבן אם הוא ייקשר לכל נגיעה

באפליקציה יש הרבה כפתורים שמובילים לכתיבה. אם כל אחד פותח פופ-אפ, המבקר יסגור אחרי השני.

**המלצה:** הפופ-אפ נפתח על **כוונת כתיבה מפורשת** בלבד: הוספת רכב, שמירה, מחיקה, העלאת מסמך, שליחת הודעה. ניווט, פתיחת כרטיס, החלפת טאב, גלילה, פילטר, הגדלה — כל אלה עובדים חופשי.

### 3. יושר לגבי נתונים קפואים, בלי לזעוק

ארבעה מסכים מציגים נתונים קפואים. תיוג כל אחד בנפרד = רעש.

**המלצה:** שורת כיתוב אחת קבועה מתחת למסגרת, "הנתונים להמחשה בלבד". זה מכסה את כל המסכים, נאמר פעם אחת, ולא מפריע.

### 4. מלכודת פוקוס במקלדת

iframe הוא מלכודת. משתמש מקלדת שנכנס עלול לא לצאת.

**המלצה:** כפתור הסגירה הוא **הפוקוס הראשון** אחרי הפתיחה. `Esc` עובד בשתי השכבות. ובמצב מנוחה, ה-iframe לא קיים ב-DOM בכלל, כך שאין מה לתקוע.

### 5. הבורר עם שתי משמעויות עלול לבלבל

אותם כפתורים מחליפים תמונה במצב אחד ומנווטים באפליקציה במצב שני.

**המלצה:** במצב פעיל, סימון הבחירה בבורר חייב להתעדכן לפי המסך שהמבקר הגיע אליו **מתוך** האפליקציה, לא רק מלחיצה על הבורר. אחרת הבורר משקר. אם זה מסתבך טכנית, עדיף לנטרל את הבורר במצב פעיל מאשר להשאיר אותו לא מסונכרן.

### 6. "התנסו במסכים" מבטיח פחות ממה שיש

הניסוח הזה זמני. **`copywriter` יחליט.** מה שחשוב מבחינת UX: הכפתור חייב לומר שזה חינם ושאין הרשמה, כי זה החסם האמיתי, לא הסקרנות.
