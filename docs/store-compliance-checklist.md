## חלק א: 🔴 פערים חיים: לא עומדים בהם עכשיו

**אלה אינם קשורים למונטיזציה. האפליקציה בחנויות ואינה עומדת בהם כרגע.**

### א-0 🔴🔴 מחיקת חשבון **אינה עובדת** למשתמשי Google ו-Apple

**הפער החמור מכולם, ונמצא 2026-09-08 בזמן העבודה על א-1.**

[DeleteAccount.jsx:46-65](../src/pages/DeleteAccount.jsx#L46) מחייב אימות מחדש **בסיסמה**:

```js
if (!confirmPassword) { setError('יש להזין סיסמה לאישור'); return; }
await supabase.auth.signInWithPassword({ email: user.email, password: confirmPassword });
```

**למשתמש שנרשם דרך Google או Apple אין סיסמה.** בקובץ **אין שום** ענף provider / OAuth / identities, חיפוש מלא מחזיר אפס. והכפתור עצמו `disabled={reauthPending || !confirmPassword}`, כלומר משתמש OAuth **אינו יכול אפילו ללחוץ עליו**.

**סדר גודל:** לפי פילוח ההרשמות האחרון, google 14, apple 8, email 2 מתוך 24. כלומר **~92% מהמשתמשים החדשים אינם יכולים למחוק את חשבונם.**

**הכללים שנשברים:**
- Apple **5.1.1(v)** + עמוד התמיכה: *"All users should be allowed to delete their accounts, regardless of where they're located."*
- Google Play, מסלול מחיקה בתוך האפליקציה שעובד

> **וזה קדם-תנאי ל-א-1.** אין טעם להוסיף ביטול טוקנים של אפל לזרימה שמשתמשי אפל לא יכולים להגיע אליה.

**העיצוב המאוחד:** אימות מחדש **לפי provider**

| provider | אימות מחדש | הערה |
|---|---|---|
| `email` | סיסמה, **ללא שינוי** | הקיים |
| **`apple` ב-iOS נייטיב** | `SignInWithApple.authorize()`, גיליון נייטיב עם Face ID | **מוכיח זהות ומחזיר `authorizationCode` באותה פעולה** ⇒ פותר את א-1 בחינם |
| `google` / `apple` בדפדפן | הקלדת מילת אישור (למשל "מחק") | OAuth בדפדפן דורש redirect שמאבד את מצב המסך |

- [ ] ענף provider בזרימת המחיקה
- [ ] אימות נייטיב מול אפל שמחזיר `authorizationCode`
- [ ] מסלול אישור-בהקלדה ל-OAuth בדפדפן
- [ ] ⚠️ זו **תוספת flow ו-states** בנתיב הרסני, ראויה למעבר `ux` על הקופי והמצבים

### א-1 🔴 `revoke_tokens` של Sign in with Apple חסר לגמרי

**הדרישה**: [Offering Account Deletion](https://developer.apple.com/support/offering-account-deletion-in-your-app/), Guideline **5.1.1(v)**: אפליקציה שמציעה Sign in with Apple **חייבת** לקרוא ל-[REST API לביטול טוקנים](https://developer.apple.com/documentation/sign_in_with_apple/revoke_tokens/) כשמשתמש מוחק את חשבונו.

**המצב:** חיפוש על `revoke_token` / `appleid.apple.com/auth/revoke` בכל `src/` ו-`supabase/`, **אפס תוצאות.** האפליקציה מציעה SIWA ומציעה מחיקת חשבון, ולא מבטלת טוקנים.

### ⚠️ החסימה האמיתית: אין לנו טוקן לבטל

`POST https://appleid.apple.com/auth/revoke` דורש **טוקן שאפל הנפיקה** (`refresh_token` או `access_token`). בדיקת הקוד מגלה שאין לנו אותו:

- [AuthPage.jsx:604-623](../src/pages/AuthPage.jsx#L604), `SignInWithApple.authorize()` לוקח את `identityToken` בלבד ומעביר ל-`signInWithIdToken`
- **ה-`authorizationCode` של אפל, שהוא מה שמחליפים ל-refresh token, לא נקלט ולא נשמר**
- ה-`refresh_token` ב-[AuthPage.jsx:949](../src/pages/AuthPage.jsx#L949) הוא של **Supabase**, לא של אפל

**כלומר זה לא "להוסיף קריאה" אלא שינוי דו-חלקי:**

**חלק 1, בהתחברות (חוסם את כל השאר):**
- [ ] לקלוט `result.response.authorizationCode`
- [ ] להחליף אותו בשרת ב-`POST https://appleid.apple.com/auth/token` ל-`refresh_token`
- [ ] לשמור את ה-refresh token, טבלה חדשה, **כתיבה וקריאה ב-service-role בלבד**, ללא שום policy ללקוח
- [ ] ⚠️ **DB migration על מסד ששיתוף עם prod**: שער 5 של CLAUDE.md חל

**⚠️ הגישה שנבחרה בפועל (2026-09-08): אימות מחדש, בלי לשמור טוקן.**

במקום חלק 1, זרימת המחיקה **מאמתת את המשתמש מחדש מול אפל** ומקבלת `authorizationCode` **טרי**. כך אין credential שנשמר, אין מיגרציית DB, **ו-8 המשתמשים הקיימים מכוסים גם הם** (הם לא היו מכוסים בגישת השמירה). אפל מרשה במפורש אימות מחדש בזרימת מחיקה.

**מה נכתב:**
- [x] `resolveReauthMode()` ב-[DeleteAccount.jsx](../src/pages/DeleteAccount.jsx), ענף `apple` גובר על סיסמה כי הוא היחיד שמחזיר את הקוד
- [x] גיליון Apple נייטיב שמאמת זהות **ומחזיר את הקוד** באותה פעולה
- [x] **edge function `apple-revoke`** ([supabase/functions/apple-revoke/index.ts](../supabase/functions/apple-revoke/index.ts)): חתימת client_secret ב-**ES256** דרך WebCrypto, החלפת הקוד ב-`/auth/token`, ואז `/auth/revoke`
- [x] נקראת **אחרי** שהמחיקה הצליחה ו**לפני** `signOut` (לפני זה היה מבטל קישור גם כשהמחיקה נכשלת; אחרי `signOut` אין session לאשר את הקריאה)
- [x] כשל **אינו חוסם** את המחיקה ואינו מוצג למשתמש, אלא נרשם ל-`app_errors`
- [ ] ⚙️ **שלושת הסודות** (זה כל מה שנשאר): `APPLE_SIWA_PRIVATE_KEY`, `APPLE_SIWA_KEY_ID`, `APPLE_TEAM_ID` ל-**Supabase → Edge Functions → Secrets**. שים לב: זה **מקום אחר** מ-Auth → Providers → Apple, שהפונקציה אינה יכולה לקרוא ממנו
- [ ] בדיקה מקצה-לקצה עם חשבון SIWA אמיתי במכשיר

**הערה:** WebCrypto מחזיר חתימת ECDSA כ-`r||s` גולמי, שזה בדיוק מה ש-JWS ES256 דורש. (Node מחזיר DER כברירת מחדל, וזו הסיבה הקלאסית ש-client_secret שנחתם ביד נדחה ע"י אפל.)

**⚙️ תלויות חיצוניות, צד Ofek, חוסמות את חלק 2:**
- [ ] ליצור **Sign in with Apple key** (`.p8`) בפורטל המפתחים
- [ ] לרשום כסודות: `APPLE_SIWA_KEY_ID`, `APPLE_TEAM_ID`, `APPLE_SIWA_PRIVATE_KEY`, `APPLE_BUNDLE_ID`

**🔴 ומשתמשים קיימים לא ניתנים לביטול.** 8 המשתמשים שנרשמו דרך אפל עד היום, אין להם טוקן שמור, ולעולם לא יהיה. אפשר רק למחוק את הרשומה אצלנו. **חלק 1 עוצר את הדימום קדימה**, ולכן הוא הדחוף, כל יום בלי הקליטה הוא עוד קוהורט שלא ניתן לבטל.

### א-2 🟢 מדיניות הפרטיות: **תוקן 2026-09-08** (נותרה ההסכמה המפורשת)

**הדרישה**: Guideline **5.1.2(i)**, בעדכון **13.11.2025**:

> You must clearly disclose where personal data will be shared with third parties, **including with third-party AI**, and obtain explicit permission before doing so.

**המצב:** [PrivacyPolicy.jsx:44](../src/pages/PrivacyPolicy.jsx#L44) אומר *"עם שירותי AI (Google Gemini) … ללא מידע מזהה"*. אבל ב-`ai-proxy` מוגדרים **שלושה** ספקים: `GEMINI_API_KEY`, `GROQ_API_KEY`, `ANTHROPIC_API_KEY`.

**שתי בעיות:**
1. **חוסר שלמות**: אם Groq או Anthropic פעילים בייצור, הם אינם מגולים.
2. **אי-דיוק בטענת "ללא מידע מזהה"**: נכון אולי לתגובות הקהילה, אבל **צ'אט היועץ שולח את מה שהמשתמש מקליד**, ובאפליקציית רכב זה כולל מספרי רישוי, שמות ומקומות. הטענה כפי שנוסחה אינה מדויקת לצ'אט.

**ובעיה שלישית שנמצאה בבדיקה:** הסעיף מנה רק את **תגובות הקהילה**. הוא לא הזכיר את **צ'אט היועץ**, ולא את **סריקת המסמכים**, ששולחת **תמונות של רישיון נהיגה, רישיון רכב וביטוח** לספק AI. זה הפער החמור מבין השלושה.

**מה נעשה (`src/pages/PrivacyPolicy.jsx`):**
- [x] סעיף 2 מונה עכשיו גם את צ'אט היועץ וגם את קריאת המסמכים והלוחיות
- [x] תת-סעיף חדש **"שיתוף עם שירותי AI"** שמונה בשם את **Google (Gemini), Groq ו-Anthropic (Claude)**
- [x] פירוט **מה נשלח בפועל** בכל משטח, טקסט בצ'אט, פוסט בקהילה, **תמונה** בסריקה, עם אזהרה מפורשת שמסמכים מכילים פרטים מזהים
- [x] הטענה "ללא מידע מזהה" הוחלפה בנוסח מדויק: התוכן נשלח **בלי מזהי החשבון** (מייל, שם, רשימת רכבים), אבל מה שהמשתמש כותב או מצלם, כן נכלל
- [ ] ⚙️ **לאמת איזה ספקים באמת מוגדרים בסודות הייצור**: הנוסח מכסה את שלושתם, אבל עדיף לצמצם למה שפעיל

**🔴 מה שנשאר פתוח, הסכמה מפורשת:** 5.1.2(i) דורש *"obtain explicit permission before doing so"*. **קישור למדיניות אינו הסכמה.** נדרשת נקודת הסכמה לפני השימוש הראשון ב-AI, וזו **תוספת flow/state ולא תיקון טקסט**, ולכן לפי ה-Playbook היא דורשת `ux` + `designer` לפני מימוש. לא נבנתה.
