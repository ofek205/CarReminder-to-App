## מה נבדק

- בניית production מלאה של Vite.
- 19 עמודי האתר בגרסת ה־HTML שנועדה למנועי חיפוש.
- כל 19 העמודים ברוחב מחשב 1440×1000 וברוחב מובייל 390×844.
- כותרת ראשית אחת בכל עמוד, RTL, נקודת ציון `main`, שמות נגישים לכפתורים ולשדות, `alt` לתמונות ומזהים כפולים.
- תמונות שבורות, גלילה אופקית, שגיאות JavaScript ושגיאות console.
- פתיחת תפריט מובייל והצגת הודעת שגיאה בטופס בדיקת רכב ריק.
- קישורים פנימיים, עוגנים, קובצי עיצוב ותמונות ב־HTML הסטטי.
- קישורי App Store ו־Google Play.
- lint מלא, שער זמני שאילתות, בדיקת אתחול ובדיקת חלונות נסיעה.

## חסימות לפני פרסום

### 1. Service Worker נשבר בכניסה לעמודי האתר

ב־`src/main.jsx` ה־Service Worker נרשם באמצעות `./sw.js`. מתוך כתובת כמו `/website/vessels/` הדפדפן מבקש `/website/vessels/sw.js`, מקבל HTML ומדווח `unsupported MIME type ('text/html')`.

הבדיקה המחמירה שחזרה את השגיאה בכל 19 העמודים, גם במחשב וגם במובייל. התוכן ממשיך להופיע, אך זו שגיאת production אמיתית ועלולה לפגוע ביכולות PWA, cache ועבודה לא מקוונת. יש להשתמש בנתיב שורש `/sw.js` ולבדוק שוב.

### 2. האתר נבנה כרגע עם noindex

`VITE_MARKETING_SITE_ORIGIN` אינו מוגדר בבנייה המקומית. מנגנון ה־SEO בכוונה יוצר במצב זה `noindex,follow`, אינו מוסיף כתובות canonical ואינו יוצר `website/sitemap.xml`.

לפני פרסום צריך להגדיר ב־Vercel את כתובת ה־HTTPS הסופית, לבנות מחדש ולוודא שכל העמודים מלבד `/website/vehicle-check` מקבלים `index,follow`, canonical מלא ונכללים במפת האתר. עמוד בדיקת הרכב צריך להישאר `noindex` כדי לא לחשוף תוצאות חיפוש אישיות במנועי חיפוש.

### 3. מצב Git אינו מתאים למסירה

הפרויקט נמצא על הענף `hotfix/find-garage-overpass-timeout` עם שינויים מקומיים רבים שאינם שמורים ב־commit. לפני העברה או העלאה יש להפריד את עבודת האתר לענף ברור ולבדוק את רשימת הקבצים לפני commit. אין צורך לשכפל את האתר לתיקייה נוספת.

## בעיות נוספות לטיפול

1. בדיקת האתחול מסיימת עם 14 הצלחות וכישלון אחד. קוד הריצה כולל את `trimmedValue`, אך סקריפט הבדיקה מחלץ את `CUSTOM_CHECKS` בלי לחלץ את פונקציית העזר ולכן נכשל במסלול התקין. זו תקלה בבדיקה ולא הוכחה לתקלה באתחול האפליקציה.
2. `npm run typecheck` אינו נקי. הבדיקה מכניסה גם קובצי JavaScript מספריות חיצוניות ומדווחת כמות גדולה של שגיאות, לצד שגיאות בפרויקט. כרגע היא אינה שער אמין לפרסום ודורשת תיקון תצורה ובניית baseline.
3. כשהתפריט הנייד פתוח, כפתור ההורדה שבכותרת נחתך בצד שמאל. התפריט עצמו עובד, אך כדאי להסתיר את הכפתור במצב פתוח או להוציא אותו מזרימת הכותרת.
4. הבנייה מתריעה על קבצים גדולים. הקבצים הבולטים הם `exceljs` סביב 940KB, קובץ האפליקציה הראשי סביב 628KB וייצוא PDF סביב 597KB לפני gzip. קובץ האתר השיווקי עצמו סביב 39KB, אך כדאי למדוד Core Web Vitals אחרי פריסה ל־preview אמיתי.
5. בסיס נתוני הדפדפנים של Browserslist ישן בשבעה חודשים.
6. ה־lint עובר ללא שגיאות אך כולל 911 אזהרות קיימות. רובן קשורות לצבעים ישירים ולמשתנים שאינם בשימוש.

## מגבלות הבדיקה

לא בוצעה בדיקה עם חשבון משתמש אמיתי, שמירת רכב, יצירת PDF עם נתונים אמיתיים, התראות מערכת או אפליקציות iOS ו־Android. סביבת staging והייצור חולקות כרגע מסד נתונים, ולכן בדיקת QA זו נמנעה מכתיבה לנתוני משתמשים. אחרי יצירת סביבת preview בטוחה יש לבצע בדיקת אורח מלאה, התחברות, הורדת PDF וטופס פנייה.

שתי השורות הקטנות בבאנר העליון, "גם באתר וגם באפליקציה" ו־"בדיקת רכב ראשונה כאורח", הוסרו. הבנייה מחדש ובדיקות ה־HTML עברו לאחר ההסרה.

נוסף `scripts/qa-marketing.mjs`, שמאפשר לחזור על בדיקת 19 העמודים בשני גדלי מסך. ברירת המחדל מחמירה ומשאירה את תקלה ה־Service Worker ככישלון עד שתתוקן.
