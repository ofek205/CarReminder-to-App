# UX: הסכמה מפורשת לשיתוף מידע עם ספקי AI

> שלב `ux` ב-Playbook. נכתב 2026-09-08. הבא: `copywriter`, ואז `frontend-design`.
> **הדרישה:** App Store **5.1.2(i)**, בעדכון 13.11.2025: *"You must clearly disclose where personal data will be shared with third parties, **including with third-party AI**, and obtain explicit permission before doing so."*
> **קישור למדיניות פרטיות אינו הסכמה.** [store-compliance-checklist §א-2](store-compliance-checklist.md)

---

## 1. UX Goal

שהמשתמש יבין **מה נשלח ולמי** ברגע שזה רלוונטי לו, יוכל לומר לא בלי לאבד את האפליקציה, ויוכל לשנות את דעתו אחר כך. ובלי לשאול אף אחד שאלה על AI לפני שהוא בכלל התקרב ל-AI.

## 2. שתי הסכמות, לא אחת

| הסכמה | מכסה | נשלח |
|---|---|---|
| **`ai_text`** | צ'אט היועץ, תגובות AI בקהילה, עצת כלי שייט | הטקסט שהמשתמש כתב |
| **`ai_images`** | סריקת מסמכים, סריקת לוחית | **תמונה** של רישיון נהיגה, רישיון רכב, ביטוח, קבלה |

**למה שתיים:** ברישיון נהיגה יש ת.ז, כתובת ותאריך לידה. בשאלה בצ'אט אין. הסכמה אחת גורפת תגרום למי שמוכן לשאול שאלה להסכים גם לשליחת מסמכים, וזה לא מה שהוא התכוון לו. ובנוסף הגייט המונטיזציוני שונה: הצ'אט בתשלום, הסריקה חינמית.

### ⚠️ ההסכמה לתמונות חייבת לכסות קדימה

שמונה משטחי `scan_extraction` **כבויים** כרגע בדגל, אבל **`plate_scan` חי** והוא `feature` נפרד שהשער לא חוסם. ובנוסף ברירת המחדל של הדגל היא **דלוקה**.

לכן נוסח ההסכמה מתאר **קטגוריה** ("מסמכים ולוחיות שתצלם") ולא רשימת משטחים. אחרת החלפת דגל אחת תתחיל לשלוח תמונות רישיונות נהיגה בלי הסכמה.

## 3. איפה זה נשמר

**בשרת, לא ב-`localStorage`.** הסכמה שנעלמת בהתקנה מחדש אינה הסכמה, וצריך להיות לה תיעוד של מה ומתי.

```sql
ai_consents(user_id, kind, version, granted_at, revoked_at)
-- kind: 'ai_text' | 'ai_images'
-- RLS: המשתמש קורא וכותב את השורות שלו בלבד
```

⚠️ **מיגרציית DB על מסד שמשותף עם prod**, שער 5 של CLAUDE.md חל. טבלה חדשה בלבד, additive, אפס שינוי בקיים.

**`user_metadata` לא מתאים** לזה. הוא client-writable ומתועד בפרויקט כ"analytics HINT only, never for security".

### `version` היא המנגנון שמחזיק את ההסכמה כשרה

אם רשימת הספקים משתנה, למשל יוסיפו ספק רביעי, **הגדלת ה-version מבקשת הסכמה מחדש**. בלי זה ההסכמה נשארת רשומה בזמן שהמידע הולך למקום שהמשתמש לא הסכים לו.

## 4. מתי נשאלים, בכל משטח

**העיקרון: ברגע שהמידע עומד להישלח, לא לפני. ולא ב-onboarding.** מי שלא נוגע ב-AI לא יישאל אף פעם, ו-~558 המשתמשים הקיימים נשאלים בהקשר בפעם הבאה שהם משתמשים.

### 4.1 צ'אט היועץ (`ai_text`)

**נשאל ב-שליחת ההודעה הראשונה, לא בפתיחת המסך.** פתיחת המסך לא שולחת כלום.

```
המשתמש מקליד ולוחץ שליחה
   → אין הסכמה → גיליון הסכמה
        ├─ הסכים  → ההודעה נשלחת מיד, בלי לחזור על הלחיצה
        └─ סירב   → ההודעה נשארת בתיבה, המסך עובר למצב "סירב"
```

⚠️ **חובה לשמור את הטיוטה.** לאבד הודעה שמישהו הקליד כדי לשאול אותו על פרטיות זה להעניש אותו על השאלה שלנו.

### 4.2 תגובות AI בקהילה (`ai_text`)

**זה המשטח השונה, ולכן הוא לא נגזר מהשניים האחרים.**

התגובה מופעלת ע"י **פרסום פוסט**, לא ע"י בקשה מ-AI. המשתמש רוצה לפרסם; ה-AI הוא שירות שנוסף מעל.

**לכן: הסירוב לא חוסם את הפרסום, הוא מבטל את התשובה.**

```
המשתמש מפרסם פוסט
   → אין הסכמה → גיליון הסכמה, ממוסגר כ"רוצה שברוך יענה?"
        ├─ הסכים  → הפוסט מתפרסם + תשובת AI
        └─ סירב   → הפוסט מתפרסם, בלי תשובת AI
```

**בשום מקרה הפוסט לא נאבד.** אם ההסכמה נכשלת או המשתמש סוגר את הגיליון, הפרסום ממשיך.

### 4.3 סריקת מסמכים ולוחית (`ai_images`)

**נשאל לפני שהמצלמה נפתחת.** אחרי שמישהו צילם את רישיון הנהיגה שלו, לשאול אותו אם מותר לשלוח אותו זה לבזבז את העבודה שלו.

```
המשתמש נוגע באריח הסריקה
   → אין הסכמה → גיליון הסכמה
        ├─ הסכים  → המצלמה נפתחת
        └─ סירב   → נפילה למילוי ידני
```

💡 **מסלול הסירוב כבר בנוי.** `SCAN_EXTRACTION_DISABLED` כבר גורם לכל משטח סריקה ליפול למילוי ידני, עם קופי קיים. הסירוב מנתב לאותו מסלול, ולכן זו העבודה הזולה מהשלוש.

## 5. מבנה הגיליון

בקשת הסכמה היא רגע של אמון. גיליון תחתון, לא מודאל, כי הוא נבדק במובייל.

```
┌──────────────────────────────┐
│         (אייקון)             │
│  שיתוף עם שירותי AI          │
├──────────────────────────────┤
│  כדי לענות על השאלה, נשלח    │  ← מה נשלח, בלשון פעילה
│  את הטקסט שכתבת לשירות AI    │
│  חיצוני.                     │
│                              │
│  · Google (Gemini)           │  ← למי, בשם
│  · Groq                      │
│  · Anthropic (Claude)        │
│                              │
│  לא נשלחים המייל, השם או     │  ← מה לא נשלח, וזה
│  רשימת הרכבים שלך.           │     מה שמרגיע
│                              │
│  מדיניות פרטיות ›            │
├──────────────────────────────┤
│ [ מאשר, שלח את השאלה ]       │  ← 52px, thumb reach
│ [ לא עכשיו ]                 │
└──────────────────────────────┘
```

**שלוש החלטות קופי:**

**"מה לא נשלח" נשאר בגיליון.** זה מה שהופך את ההסכמה מ"תן לי הרשאה" ל"הנה הגבול". בלעדיו ההסכמה נראית פתוחה יותר ממה שהיא.

**הכפתור אומר מה יקרה** ("שלח את השאלה" / "פתח את המצלמה" / "פרסם עם תשובה"), לא "אישור". תווית שמתארת את הפעולה במקום את הטופס.

**"לא עכשיו" ולא "דחה".** הסירוב הפיך, והתווית לא צריכה להישמע סופית.

## 6. מה קורה למי שסירב, בכל משטח

| משטח | אחרי סירוב |
|---|---|
| צ'אט היועץ | המסך מוצג עם הסבר וכפתור "אפשר שיתוף". הטיוטה נשמרת. **לא מסך ריק** |
| קהילה | הפרסום עובד רגיל, בלי תשובת AI. **בלי תזכורת בכל פרסום** |
| סריקה | האריח מושתק עם "נדרש שיתוף עם AI", בנוסח תבנית ה"כרגע לא זמין" הקיימת |

⚠️ **לא לשאול שוב באופן אוטומטי.** מי שסירב בחר. בקשה חוזרת בכל שימוש היא הטרדה, ובחנות היא נקראת dark pattern. הבקשה חוזרת **רק** אם המשתמש יזם, או אם ה-`version` עלה.

## 7. ביטול הסכמה

**הגדרות → שורת "שירותי AI"**, לא קבור בפרופיל.

```
┌──────────────────────────────┐
│ ← שירותי AI                  │
├──────────────────────────────┤
│ שיתוף טקסט                   │
│ צ'אט היועץ ותגובות בקהילה    │
│                    [ ●——  ]  │
│ אושר ב-8.9.2026              │
├──────────────────────────────┤
│ שיתוף תמונות מסמכים          │
│ סריקת רישיון, ביטוח וקבלות   │
│                    [  ——○ ]  │
├──────────────────────────────┤
│ למי נשלח, ומה לא נשלח ›      │
└──────────────────────────────┘
```

**כיבוי מיידי, בלי אישור.** ביטול הרשאה הוא הכיוון הבטוח, ואישור עליו הוא חיכוך שמגן על אף אחד.

⚠️ **מה שכיבוי לא עושה:** תגובות AI שכבר פורסמו בקהילה נשארות. אי-אפשר למחוק שרשור שאחרים מגיבים בו, וצריך לומר את זה בשורה אחת ולא להשתיק.

## 8. מצבים

| מצב | מה מוצג |
|---|---|
| טרם נשאל | המשטח נראה רגיל. הגיליון עולה בפעולה |
| בטעינה | האריח/הכפתור עם skeleton, **לא מצב "סורב"** שיהבהב |
| הוסכם | רגיל |
| סירב | לפי הטבלה ב-§6 |
| כתיבת ההסכמה נכשלה | הגיליון נשאר עם "השמירה נכשלה, נסה שוב". **לא ממשיכים לשלוח** |
| קריאת ההסכמה נכשלה | **fail-closed: AI חסום** + "נסה שוב" |
| offline | AI דורש רשת בכל מקרה, ולכן זה לא מצב נפרד. אבל **כתיבה שנכשלה אינה הסכמה** |
| `version` עלה | נשאל מחדש, עם הסבר שמה שנשלח השתנה |

### ⚠️ fail-closed, בניגוד לתבנית הקיימת

`aiScanGate` הוא `defaultOnError: true` **במכוון**, כדי שתקלת רשת לא תהרוג סריקות לכולם. **ההסכמה חייבת להיות ההפוך.** כשל בקריאה שנחשב "הסכים" פירושו שליחת מסמכים בלי הסכמה, וזה סיכון משפטי ולא אי-נוחות.

## 10. סיכונים

| סיכון | הפחתה |
|---|---|
| **הגיליון בקהילה יוריד פרסומים** | הסירוב לא חוסם פרסום, והמסגור הוא "רוצה תשובה?" ולא "אשר כדי לפרסם" |
| טיוטה נאבדת בצ'אט | חובה לשמור. AC מפורש |
| מי שסירב יישאל שוב ויתעצבן | בקשה חוזרת רק ביוזמתו או ב-`version` חדש |
| ההסכמה תיראה כמו עוד cookie banner | נשאלת בהקשר ולא ב-onboarding, ומתארת מה **לא** נשלח |
| הסכמה שתיכתב ותיכשל תיחשב כניתנה | כתיבה נכשלת עוצרת את השליחה |
| הדלקת דגל הסריקה תעקוף הסכמה | הנוסח מתאר קטגוריה, לא משטחים |
| ~558 קיימים ייתקלו בזה בבת אחת | בהקשר ולא ב-onboarding, ולכן מתפרס לפי שימוש אמיתי |

## 11. מחוץ ל-scope

- גייט הצ'אט לתשלום. דורש את תשתית המסלולים (שלבים 1 עד 5), חסום על שלב 0
- תיוג שני נתיבי ה-AI שאין להם `surface` (PostCreateDialog, aiAdvice). צריך לקרות, אבל זה תיקון נפרד
- הסכמה לספק ספציפי. הכל או כלום לכל קטגוריה
